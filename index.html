Цель работы

Ознакомиться с моделью гибкой разработки программного обеспечения, развернуть приложение на Heroku, ознакомиться с системой контроля версий Git.

Эволюция архитектур ИС

1. Монолитная архитектура

На одном компьютере работали и приложения, и база данных. Пользователи работали у «тонких» терминалов. Много недостатков

2. Клиент-серверная архитектура

Выделенный сервер баз данных + «толстые клиенты» пользователей. Разгрузка сервера БД

3. Многоуровневая архитектура

Логика приложений вынесена на сервер приложений, пользователи работают на «тонких» клиентах через браузеры. Современный стандарт

Методологии разработки ПО

Критерий Каскадная (Waterfall) Гибкая (Agile)
Процесс Последовательный Итеративный
Обратная связь После завершения После каждой итерации
Стоимость и сроки Определены заранее Сложно оценить
Управление Простое Требует опыта

Extreme Programming (XP) — одно из известных практических применений Agile.

Heroku как PaaS-платформа

  • Поддерживает Java, Node.js, Scala, Clojure, Python, PHP
  • Собственный DNS-сервер
  • Виртуальные процессы — «dynos», распределённые по виртуальной сетке
  • Поддержка Git и интеграция с GitHub
  • Быстрый деплой без собственной инфраструктуры

Порядок выполнения работы

  1. Зарегистрироваться в Heroku
  2. Создать тестовое приложение на Python (или другом языке)
  3. Задеплоить приложение на Heroku
  4. Внести изменения в код и снова задеплоить
  5. Ознакомиться с дополнительными возможностями Heroku и Git

Контрольные вопросы

1. Почему Agile становится всё популярнее?

Заказчик видит результат после каждой итерации и может корректировать требования. Это повышает гибкость и снижает риски.

2. Преимущества PaaS перед IaaS?

PaaS избавляет от необходимости управлять инфраструктурой: ОС, серверы, масштабирование берёт на себя провайдер. IaaS же требует самостоятельной настройки.

3. Зачем команды add, commit, push в Git?

add — добавляет файлы в индекс, commit — фиксирует изменения локально, push — отправляет их в удалённый репозиторий.

4. Преимущества Heroku перед локальным окружением?

Быстрый деплой, автоматическое масштабирование, доступность из любой точки мира, не нужно настраивать серверы и следить за инфраструктурой.
